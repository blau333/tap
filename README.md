# Коло — социальная сеть на Rust

Полноценное веб-приложение на Rust: сервер сам рендерит HTML-страницы,
данные хранятся в **MariaDB**. Лента из 6 постов в закруглённых карточках
+ нижняя навигация (Сообщения / Сообщества / Главная / Профиль) — теперь
всё живёт в реляционной БД, а не захардкожено в разметке.

## Стек

- **[axum](https://docs.rs/axum)** — HTTP-сервер и роутинг
- **[sqlx](https://docs.rs/sqlx)** — асинхронный доступ к MariaDB/MySQL
  (без ORM, обычные SQL-запросы)
- **[askama](https://docs.rs/askama)** — HTML-шаблоны, проверяются на
  этапе компиляции
- **[tokio](https://docs.rs/tokio)** — асинхронный рантайм
- **MariaDB 11** — поднимается через Docker Compose

## Запуск через Docker Compose (рекомендуется)

Нужен только Docker и Docker Compose.

```bash
docker compose up --build
```

Это поднимет два контейнера:

- `kolo-mariadb` — MariaDB 11 с базой `kolo`, пользователем `kolo` / `kolo`
  (данные сохраняются в volume `kolo_db_data`, переживают перезапуск)
- `kolo-app` — само приложение, ждёт готовности БД (healthcheck) и
  подключается по `DATABASE_URL=mysql://kolo:kolo@mariadb:3306/kolo`

При первом запуске приложение само создаст таблицы и засеет демо-данные
(7 пользователей, 7 постов, 4 сообщества, 4 диалога).

Сервер будет доступен на **http://localhost:3000** — открывается страница
регистрации; после отправки формы данные реально сохраняются в БД
(имя, email → handle, инициалы аватара, пароль — как SHA-256 хеш, не в
открытом виде), создаётся сессия (HttpOnly-cookie `kolo_session`) и вас
перекидывает на `/feed`.

Остановить и убрать контейнеры:

```bash
docker compose down          # оставить данные в volume
docker compose down -v       # удалить и данные тоже
```

## Запуск без Docker (локальная MariaDB/MySQL)

1. Поднимите MariaDB или MySQL и создайте базу и пользователя:

   ```sql
   CREATE DATABASE kolo CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'kolo'@'%' IDENTIFIED BY 'kolo';
   GRANT ALL PRIVILEGES ON kolo.* TO 'kolo'@'%';
   FLUSH PRIVILEGES;
   ```

2. Укажите строку подключения (по умолчанию используется
   `mysql://kolo:kolo@127.0.0.1:3306/kolo`, можно переопределить):

   ```bash
   export DATABASE_URL="mysql://kolo:kolo@127.0.0.1:3306/kolo"
   cargo run
   ```

Нужен Rust 1.80+ (проверялось на 1.89 — на старом тулчейне 1.75
транзитивные зависимости не соберутся из-за `edition2024`; обновите через
[rustup](https://rustup.rs)).

## Маршруты

- `/` — страница регистрации (входная страница сайта)
- `/login` — вход по email + паролю (GET — форма, POST — обработка)
- `/logout` — выход (POST, уничтожает сессию)
- `/feed` — лента (6 последних постов), доступна только после входа
- `/communities` — список сообществ (после входа)
- `/messages` — список диалогов (после входа)
- `/profile` — профиль текущего пользователя со своими постами

Без сессии все страницы, кроме `/`, `/login` и статики, редиректят на
`/login`. Сессии хранятся в таблице `sessions` (токен → пользователь,
срок жизни 30 дней).

Демо-аккаунты из сидов: вход по email вида `marina.k@kolo.demo`,
пароль у всех — `kolo123`.

## Что тут по-настоящему динамическое

Все страницы рендерятся на сервере из данных MariaDB: посты, сообщества,
диалоги и профиль подтягиваются через SQL-запросы (`src/handlers.rs`),
а не зашиты в HTML. Иконки категорий и цветовые акценты тоже хранятся в
базе (`icon_key`, `accent`, `accent2`) — новый пост с новой категорией
подхватит нужную иконку и цвет автоматически.
